# Otium — задача на доработку API и диаграмма последовательности

Учебный проект в рамках курса «Системный анализ» (Яндекс Практикум, 2026). Модуль: проектирование интеграций, работа с API, диаграммы последовательности, командная работа.

## Контекст

Otium — сервис фильмов и сериалов с каталогом и библиотекой пользователя. Бизнес-задача — дать пользователям возможность сортировать каталог по рейтингу зрителей и рейтингу кинокритиков с сохранением ранее применённых фильтров. Изменения затрагивают три сервиса backend: Films Server, Series Server, Web Server. Задача проекта — оформить полное техническое задание на доработку с диаграммой последовательности и провести командную ретроспективу.

## Ключевые технические решения

| Компонент | Изменение |
|-----------|-----------|
| Films Server API | Добавлено поле `criticsRating` в `/films/list` и `/films` |
| Series Server API | Добавлено поле `criticsRating` в `/series/list` и `/series` |
| Web Server API | Добавлены query-параметры `sortBy` (rating / criticsRating) и `direction` (asc / desc) в `/content/list` |
| Обработка null | Контент без `criticsRating` отображается в конце списка независимо от направления сортировки |
| Взаимодействие | Параллельные запросы Web Server → Films + Series Server, объединение результата на бэкенде |

## Методология и инструменты

- **Sequence Diagram** — UML-нотация, фрагменты `par` (параллельные вызовы) и `opt` (условные ветки)
- **API-first design** — контракт эндпоинтов и полей до реализации
- **Start / Stop / Continue** — формат ретроспективы
- **Инструменты:** draw.io, Microsoft Word

## Чему научился

- Проектировать доработки распределённой системы (несколько бэкенд-сервисов + UI) как единое ТЗ
- Формализовать контракты API: эндпоинты, query-параметры, поля ответа, обработка граничных случаев (null, пустая выдача)
- Читать и рисовать sequence-диаграммы с параллельными и опциональными фрагментами
- Работать в команде: распределять задачи, синхронизироваться по статусам, проводить ретроспективу
